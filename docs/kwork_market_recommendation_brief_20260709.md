# Kwork Market Recommendation Brief

Дата: 2026-07-09

## Цель

Показать фрилансеру в выбранной рубрике, что именно стоит искать у покупателей прямо сейчас.

## Что не нужно

- Не показывать пользователю внутренние seed-имена вроде `broad_low_offer`.
- Не хардкодить фиксированные запросы как готовый совет.
- Не делать общий совет по всему рынку без привязки к рубрике.
- Не держать запасной список тематик для случая, когда по рубрике мало данных.

## Что нужно

- Для каждой рубрики строить отдельный мини-обзор спроса покупателей.
- На вход ИИ отдавать сырые данные только по текущей выбранной рубрике: лоты, заголовки, описания, цены, отклики, продавцов, концентрацию, частые слова, бюджет, сигналы спроса и историю покупателей.
- На выход ИИ должен сам предлагать, что искать фрилансеру именно в этой рубрике.
- Рекомендации должны быть на русском.
- Для каждой рекомендации сразу показывать количество найденных лотов/заказов.

## Логика

Рубрика -> анализ данных этой рубрики -> список запросов и направлений, которые фрилансеру стоит искать.

Каждый сформированный запрос выполняется с тем же `category_id` выбранной рубрики. Поиск по `categories=all` в этом пользовательском сценарии запрещён.

## Формат результата

- `query`
- `count`
- `priority`
- `why`
- при необходимости `budget`, `competition`, `examples`

## Смысл для интерфейса

Это должен быть блок `Что искать сейчас`: AI-рекомендатель по текущей рубрике, а не блок со служебными окнами поиска.
Внутренние `*_low_offer` и похожие seed-окна не показываем как советы; они могут жить только как контрольные окна под отдельным режимом.

## Как будет после исправления

- Верхний блок со сводкой остается: сколько окон прогнали, сколько лотов нашли, сколько без откликов, сколько с малой конкуренцией.
- Нижний блок переименовывается в `Что искать сейчас` и заполняется AI-рекомендациями по выбранной рубрике.
- ИИ показывает только русские запросы и направления, выведенные из данных текущей рубрики; внутренние `*_low_offer` остаются скрытыми под режимом `Показать контрольные окна`.
- У каждой рекомендации сразу есть `count` и короткое `why`; при необходимости показываются `budget`, `competition`, `examples`.

## Каноническая трактовка

- Рекомендации строятся по выбранной рубрике и её найденным лотам, а не по фиксированному списку запросов и не по рынку целиком.
- Срез внутри рубрики влияет только на навигацию и статистику. Он не сужает данные, которые ИИ использует для блока рекомендаций: источником остаётся вся выбранная основная рубрика.
- В ИИ отдаются все сырые данные по рубрике: лоты, заголовки, описания, цены, отклики, продавцы, концентрация, частые слова, бюджетные окна, сигналы спроса и история покупателей.
- ИИ сам расставляет приоритеты и формирует запросы; блок смежных рынков отдельно не выносится.
- Если выбранная рубрика `mini apps`, в выдаче могут появиться Telegram/mini-app направления, потому что они следуют из данных этой рубрики; если рубрика `сайты`, запросы должны быть сайт-специфичными.
- Ранжирование строится по спросу, конкуренции, бюджету и откликам.
- Любые внутренние `*_low_offer` окна — это только контрольная диагностика и никогда не трактуются как готовые рекомендации для пользователя.
- Если данных недостаточно, интерфейс сообщает об этом. Он не подставляет Telegram, AI, Python, broad или любую другую заранее заданную тему.

## Пример

- `WordPress — 6905 лотов`
- `Настройка сайта — 1559`
- `Защита и лечение сайта — 930`
- `Ускорение сайта — 790`
