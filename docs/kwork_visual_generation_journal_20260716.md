# Журнал переработки визуалов Kwork — 2026-07-16

## Цель

Сделать генерацию обложек и портфолио-карточек предметной и качественной для любой категории услуг, а не только для дизайна. Убрать обязательный текст поверх изображения и гарантировать использование `gpt-image-2` без скрытого понижения модели.

## Исходные симптомы

- Обложки выглядят как повторяющиеся абстрактные шаблоны и плохо показывают реальный результат услуги.
- На готовое изображение накладывается крупный заголовок с затемнением нижней части.
- Портфолио-карточки похожи на вручную собранные бренд-борды независимо от исходного запроса.
- Для запроса о минималистичном сайте программиста ожидается полноценный правдоподобный сайт, а не набор условных геометрических блоков.

## Подтвержденные факты до изменений

1. Основной payload обложки выбирает модель из `KWORK_COVER_IMAGE_MODEL`, затем `PROPOSAL_IMAGE_MODEL`, затем использует `gpt-image-2` по умолчанию.
2. При ответе image API `400` или `422` код автоматически повторяет запрос через `gpt-image-1`, а затем еще раз через `gpt-image-1` с размером `1024x1024` и качеством `standard`.
3. После успешной генерации может вызываться Pillow-функция `_overlay_cover_offer`, которая затемняет нижнюю часть и печатает поверх изображения заголовок и подзаголовок.
4. Локальный fallback `_generate_local_cover_png` рисует фиксированную абстрактную композицию из панелей, кругов, линий и условного телефона. Он не способен предметно показать услугу.
5. Текущий prompt brief уже содержит отдельные советы для web/software и design, но остается набором общих правил и зависит от LLM-переписывания промпта. Полная категорийная маршрутизация еще не подтверждена.

## Решения и проверки

### Реализовано

1. Удалены Pillow-overlay, нижний градиент и обязательные поля заголовка/подзаголовка из рабочего экрана публикации.
2. Удалён production-путь локальной абстрактной обложки. Ошибка image API теперь возвращает непубликуемый `error`, а не картинку со статусом `generated_local_fallback`.
3. Image-модель зафиксирована на `gpt-image-2`. Любое другое значение `KWORK_COVER_IMAGE_MODEL` отклоняется; fallback на `gpt-image-1` удалён.
4. Для сетевых `429/5xx` и transport errors разрешён только повтор того же payload через `gpt-image-2`, без смены модели, размера или качества.
5. В sidecar и API-результат теперь пишутся requested model, reported model, способ верификации, размер, качество, endpoint, request id, latency и retry errors.
6. Пять обязательных работ портфолио больше не рисуются локальными шаблонами про кириллицу. Они генерируются отдельными service-specific запросами через тот же строгий image pipeline.
7. Введена маршрутизация визуала по содержанию услуги: web/software, branding/design, marketing/content, writing/translation, video/audio, legal/finance/business, education, beauty/wellness, fitness/health, food/hospitality, architecture/interior, craft/product и общий профессиональный fallback.
8. Каждая стратегия задаёт конкретное доказательство результата в режимах `artifact`, `process` или `outcome`, подходящий визуальный стиль и доменные клише, которые нельзя использовать.
9. Prompt contract теперь требует один цельный edge-to-edge визуал и запрещает presentation board, case-study slide, moodboard, contact sheet, split screen, before/after, multi-panel collage, floating screens, device stack, декоративную геометрию и добавленный рекламный текст.
10. Текст разрешён только внутри реального изображаемого результата, когда он естественно нужен сайту, интерфейсу, документу или брендингу. Внешний заголовок обложки запрещён всегда.
11. История прошлых обложек фильтруется по текущей категории/классификатору и версии нового pipeline. В prompt передаются только названия для контроля повторов: старые PNG, prompt-тексты и visual style больше не используются как положительные референсы.
12. Обложки конкурентов используются как negative evidence: vision-анализ ищет шаблоны и слабые метафоры, которые следует исключить, а не стиль, которому нужно подражать.
13. Добавлен fail-closed post-generation vision quality gate на `gpt-5.6-terra`. Он проверяет соответствие услуге, предметность, отсутствие poster/collage/overlay/abstract filler, композицию, перспективу и текстовую политику. При reject выполняется одна корректирующая генерация тем же `gpt-image-2`; повторный reject или недоступный QA блокирует результат.
14. Pixel-QA применяется не только к обложке, но и к каждому сгенерированному portfolio asset. Портфолио допускается к публикации только после успешного QA.
15. Введён marker `gpt-image-2-concrete-v3`. Старые Pillow boards, `gpt-image-1`, local fallback, ассеты без passed QA и предыдущая `v2` с разрешёнными contact details больше не переиспользуются и не проходят live preflight как новые.
16. Для `web_software + artifact` закреплено отдельное правило: интерфейс продукта занимает весь кадр напрямую. Запрещены человек, руки, монитор, ноутбук, телефон, стол, комната, клавиатура, книги, кофе, растения и lifestyle-реквизит.
17. Art-direction prompt пишет `gpt-5.6-terra`; финальные пиксели создаёт только `gpt-image-2`; `gpt-5.6-terra` затем независимо проверяет готовый PNG.
18. Короткие латинские keywords (`ui`, `ux`, `web`) теперь ищутся как отдельные токены, а generic-слова вроде «дизайн» имеют пониженный вес. Fallback-описание очищено от web-specific слов, которые ошибочно уводили еду, beauty и другие услуги в `web_software`.
19. Portfolio specs расширены до десяти разных ракурсов, поэтому explicit/manifest count `6..10` больше не создаёт заведомо неполный набор.
20. Для prompt-writer задан exact provider/model `openai + gpt-5.6-terra`, provider fallback и reference-image route отключены. Terra получает только текстовый service brief, category strategy, negative evidence и прошлые названия. При недоступности Terra используется строгий локальный fallback prompt; скрытого перехода на Groq/DeepSeek больше нет. Sidecar context сохраняет requested prompt provider/model и attempts.
21. Email, URL/domain, телефон, `@handle`, QR и любые contact details запрещены везде, включая естественный контент интерфейса/документа. Старый PNG с email отклонён Terra и инвалидирован повышением версии pipeline.
22. Direct QA и prompt writer повторяют exact Terra-запрос по нескольким `OPENAI_API_KEYS`; невалидный первый ключ больше не выключает весь fail-closed pipeline.

### Внешние ориентиры

- OpenAI Image Generation guide и prompting guide: предмет, композиция, ограничения и итеративное уточнение должны быть явно описаны; `gpt-image-2` поддерживает direct Images API, landscape sizes и quality controls.
- NN/g: релевантные предметные изображения запоминаются лучше декоративных и generic visuals.
- Визуальные отчёты 2026 использованы только для treatment-слоя: ambient realism как базовый режим, tactile/editorial для материальных категорий, body realism для fitness; стиль не заменяет реальный предмет услуги.

### Остаточный риск

- Exact served image model можно подтвердить только если внешний gateway возвращает поле модели или предоставляет собственный audit log. В текущем ответе такого поля нет, поэтому UI показывает `request logged`, а не ложное `model verified`.
